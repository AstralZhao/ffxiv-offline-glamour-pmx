# 幻化柜 Demo

首次配置是独立窗口，只选择游戏目录或导入资源包。之后的“设置”分“资源、场景、存储”三页；存储页可查看软件文件占用和清理旧缓存，当前角色缓存、预设、模版、收藏与资源文件保留。统计和清理在后台进行。

“投影模版”中选中一套模版，点击“生成导出码 → 复制导出码”即可分享。点击“导入模版码”，粘贴后可修改名称并“新增模版”；导入保留已有记录，不会立即换装。代码包含装备和双染色，不含角色外观。旧保存记录无需迁移。另可使用“批量导出/批量导入”，勾选多套模版保存为一个.hggtemplates文件，或从文件中选择需要的模版新增；同名也新增，不覆盖已有记录、不立即换装。

角色预设支持人族女性（中原之民、高地之民）、猫魅族男性/女性（逐日之民、护月之民）、敖龙族女性（晨曦之民、暮晖之民）和维埃拉族男性/女性（密林之民、山林之民）。开发版首次启动会添加独立示例，之后保留你的修改；原有 `test.dat` 继续保留。范围与验证见[人女适配](../docs/hyur-female-adaptation.md)、[猫男适配](../docs/miqote-male-adaptation.md)、[猫娘适配](../docs/miqote-female-adaptation.md)、[兔娘适配](../docs/viera-female-adaptation.md)、[兔男适配](../docs/viera-male-adaptation.md)。

“新建预设”可选择已支持的角色类型、部族和名称，生成独立DAT并预览。同名自动另存。已有预设的性别固定，编辑和保存接口均禁止改变；其他性别通过新建或导入另一份预设使用。男性不显示胸围选项，菜单和颜色按性别分别缓存。

便携软件包双击 **幻化柜.exe**，首次启动可选择“使用游戏目录”或“导入资源包”，保存后自动记住。“导入资源包”选择独立的`.ff14resources`文件，校验后保存在软件`resources`目录，无需原游戏安装目录。已有匹配国服客户端可在“设置”中导出资源包。以后从“设置”切换资源来源，保存并应用会在当前绘制结束后重新加载；版本失效时重新配置。运行环境随包提供，无需安装或选择Python。

资源包与客户端分别生成，当前只保留项目根目录的 **幻化柜资源包-全种族精简.ff14resources**，约14.02 GiB。默认导出会按依赖精简并重新整理索引，保留全部种族资源和各族装备变体，不降低模型/贴图质量；导出、导入均有进度并支持取消。旧完整包、候选包和旧版测试展开目录已清理。迁移软件时保留已导入的`resources`目录。详见[全种族精简资源包](../docs/compact-all-race-resources.md)。

右下角显示“泠雨@沃仙曦染”，旁边“操作说明”可随时打开完整使用指南。标签下拉框支持直接输入文字搜索已有标签，展开最多显示10项，更多内容使用滚轮浏览。

导入预设时同时准备并保存静态角色缓存；默认`test.dat`也已预先准备。切换优先使用最近4个角色的内存缓存，重新启动后复用磁盘缓存；预设内容、国服资源或相关渲染实现变化时重新生成。编辑外观的“更新模型”和“保存预设”仍分开。缓存机制及实测见[角色预览缓存](../docs/character-preview-cache.md)。

开发时双击项目根目录的 **幻化柜.exe**（或兼容的 **启动试衣客户端.cmd** / **启动试衣Demo.cmd**），直接运行`demo`源码，不依赖生成的软件包。左侧装备目录、中央三维预览、右侧当前模版，顶部切换和编辑角色预设。不需要启动游戏或本机网页服务。软件使用随目录提供的Python 3.11.9、NumPy、Pillow、PySide6 6.8.3和Windows Direct3D 11，优先使用独立显卡，无独显时使用可用硬件显卡。

D3D11在客户端原生窗口里直接显示，模型帧不经过GPU读回、PNG编码、HTTP传输或网页画布。原始材质先绘入FP16目标，最后在GPU上转换到窗口交换链。窗口大小改变时重建显示目标，保持原始材质流程。静态角色只在视角、尺寸或模版改变时重绘，连续拖动会合并到最新相机状态，不排队播放过时视角。

启动时先显示完整界面和加载动画，再后台准备角色与装备图标。加载角色、更新模型和换装绘制时显示旋转提示，并保留上一帧；相机拖动只在底部显示小提示，完成或失败后自动停止。

默认包含你的`test.dat`，首次启动会复制到软件根目录的`presets/test.dat`。预设列表只使用软件目录中的副本；顶部的“导入预设”按钮会新建一份原生`.dat`副本，同名自动另存。游戏里的原文件保持只读。

如果预设文件已导入但对应模型暂时无法加载，会保留文件和原画面，并提供编辑新文件的入口；可以先修改、保存，再单独更新模型。文件格式错误仍会明确拒绝导入。

点击顶部“编辑外观”，可修改发型、脸型、五官、身高、胸围、尾巴、颜色和彩绘等。“更新模型”只预览修改，不改所选DAT；“保存预设”只写入当前软件DAT，不更新画面。两项操作相互独立，界面会提示模型与文件是否一致。更新模型后会关闭窗口方便观察，再打开时保留尚未保存的预览。装备、染色和相机继续保留。首次生成新外观需要稍等；未能生成时保持原模型和文件。两个部族均可尝试；发型列表来自国服创建菜单，未知可见结构仍会提示原因。

- 按部位搜索名称、编号或标签。多个词用空格分隔，要求同时满足；`#礼服 #双染色` 或 `标签:礼服` 只匹配标签。目录全量开放，不限制获取、职业和等级。
- “图标 / 列表”切换，图标模式只显示装备图标，星标表示收藏，叠放标记和角标数字表示同模目录；悬停显示名称和标签，单击进入目录选择具体款式，单件装备直接试穿。装备与同模目录均按每页60项分页，可上一页、下一页或输入页码跳转；返回目录保留原页和滚动位置。
- 装备按同一部位、同一基础模型编号归为同模目录。目录名称和原始游戏图标采用整组中染色区最多的装备；数量相同时优先较新的装备编号。点击目录选择具体款式，返回时保留原搜索、已加载的分页和进入前的滚动位置。
- 点击装备换装，点击右侧模版卡片上的两个染色按钮分别染色。区域数量及染剂名称来自国服本机数据。
- 左键拖动旋转和俯仰，右键拖动平移，滚轮缩放；工具栏可切正面、侧面、背面或还原相机。
- 点击“保存模版”后，可从“投影模版”重新试穿。文件保存在`artifacts/demo`，不会改动游戏角色或安装目录。
- 武器不在软件范围内。

当前目录有20,519件防具和饰品。所有条目都可以发起共用渲染，部分特殊材质、骨架驱动和遮盖组合仍未实现；遇到这些情况会保留上次成功画面并显示原因。目录开放不代表每件装备均已成功绘制。

这些条目归为5,211组模型目录，左右戒指共用款式来源。搜索任何成员名称或编号都能找到所属目录，目录代表不会随搜索结果改名。原色变体和染色能力仍按具体装备保留。

防具和饰品共享本机EQDP模型选择与PBD逐层变形路径；不会因为共用模型来自其他基础体型就一律拒绝。没有本机资源或仍缺少实现的结构会明确提示。

头饰、衣服可按EST加载原始额外骨架，并连接到预设的固定站姿。变形缺少某个额外关节时，沿文件中的真实父级继承，不按名称猜测或填单位矩阵。头饰固定使用原始闭合面罩参考状态；本版没有面罩切换、衣物摆动或装备物理动画。身体遮盖头部和高领遮盖头甲护颈也接入共用规则。

已接入滚动纹理、丝袜和玻璃三类原始着色程序：滚动纹理保持固定时间；丝袜读取额外的贴图坐标和原生皮肤材质；玻璃在不透明部件之后合成透射颜色与反射。它们仍使用原始染色表。当前是固定预览条件下的实现，尚未完成这些材质与游戏画面的逐项一致性确认。

普通半透明材质与`charactertransparency`使用原始颜色/透明度输出，在不透明部件之后排序合成；头发继续保留原有的主体和发梢两段流程。装备中的纹身、遮蔽材质复用既有叠加通道。相机会为翅膀等实际可见的大体积装备扩大取景，缩放范围为0.25至4倍。

装备贴花按原生IMC编号读取，使用独立的中性颜色乘数，不继承脸部彩绘颜色。头发按国服帽下发型模式控制，分别隐藏头顶、后发或全部头发，并应用原始帽下形变。预览处于未骑乘的固定站姿，因此坐骑EVP效果抑制标记不会阻止装备加载。

腰部、腿部护片、靴筒和护膝的遮盖按国服客户端条件组合，使用原始`shp_kos`、`shp_sho`等形变；尾部开口按预设种族筛选。长衣与裤靴模版不会再因为腿部护片标记而一律拒绝。

高领与头盔护颈、手套与上衣袖口按国服成组优先级和部位开关取舍；连体衣自身也会响应靴筒裁切。处理原始部件属性及模型形变，不改模型尺寸来掩盖交叠。

完全被装备遮住的饰品保留选择和染色，暂不加载绘制资源；脱下遮盖装备后自动恢复显示。已经隐藏的子网格上有形变重叠时，也不会再阻止整个模版。

连体衣遮住的防具、关闭显示的头饰也只保留选择与染色，不准备不可见模型和材质；仍会检查装备部位及染色是否合法。重新显示时恢复完整加载。隐形装备继续使用原始身体/内衣与占位网格，不一律当成空模型。

多个装备遮盖规则同时改变同一位置时，按原始模型文件中的形变顺序组合，后面的替换覆盖前面的；不再因为可见形变重叠而直接拒绝模版，也不依赖试穿的先后顺序。

少量装备引用的可选材质动画文件在本机不存在时，允许显示原始静态材质，并在预览下方提示。实际存在但尚未解读的动画文件仍会明确报错；这不代表已经实现材质动画播放。

当前统一关闭装备的附加粒子特效，只显示原始装备模型和材质，带特效的装备也可以正常试穿主体。特效读取和部分绘制代码保留供后续完善，完整实现后再提供显示开关；现阶段不需要加载AVFX或等待特效验证。

衣服材质本身的自发光继续显示，并通过显卡上的辉光合成呈现光晕（如新生女王礼服的蝴蝶结和裙侧）。它与附加粒子特效分开；颜色和发光区域来自原材质，辉光强度采用统一固定预览条件。

预览使用真实模型、骨架、原始材质与现有国服独立D3D11渲染流程。模型和骨架驻留并复用；未提供动作、表情或姿势编辑。客户端记录上次预设、已绘制但未保存的外观、模版及相机；文件被外部修改时加载实际新文件，不自动覆盖。此原型不代表第四阶段或全部装备外观还原已完成。

如需指定其他目录，可运行：

```powershell
& 'G:/Tools/Anaconda3/python.exe' -X utf8 demo/launch.py --game '游戏安装目录' --preset '外观预设.dat'
```

关闭客户端会先结束当前GPU操作再释放窗口资源。启动错误记录在`artifacts/demo/client-startup.log`，启动失败时命令行会暂停；模型准备日志在`artifacts/demo/demo.log`。所有导入副本和模版都留在项目内。旧网页原型仍可手动运行`demo/app.py`，保留作兼容入口；客户端本身不启动或依赖该服务。文件保存保留SHA冲突检查。

界面会随窗口变窄收紧侧栏，相机工具分行显示；默认窗口大小按屏幕可用区域设置。预设编辑按发型与体型、五官细节、颜色与彩绘分组。重装界面依赖时，使用 `demo/requirements-ui.txt`，安装目标为 `artifacts/runtime/pyside6-6.8.3`；正常运行不会自动下载依赖。

右键装备图标或模版卡片可查看详情、编辑多个标签及收藏。悬停装备可查看名称和标签。“保存标签”只保存标签；独立的收藏按钮立即保存收藏状态，并保留尚未保存的标签草稿。自定义标签和收藏会长期保存在软件目录的 `artifacts/demo/equipment-library.sqlite`，不写游戏文件。武器不生成标签或进入列表。

自动标签不再添加部位，旧的自动部位标签在下次启动时清理，用户标签保留。遮面、连体、长筒、过膝等覆盖类建议来自原装备模型配套的国服EQP规则；礼服、裙装、运动等风格仍是名称建议，详情会注明来源，均可纠正或删除。这不是完整的模型图像识别，尚未自动判定颜色、花纹或材质。染色能力标签保留。

装备收藏与“投影模版”分开：收藏或取消收藏后立即更新星标，但当前列表、同模返回和翻页不会重新排序；下一次搜索（也可按回车）、点击“刷新”或改变筛选时才按收藏优先排列。收藏的款式在其同模目录内优先，包含收藏款式的目录也优先，但目录名称和图标始终按最多染色区选代表。可点“★ 收藏”只看收藏，标签下拉可连续选择多个标签（同时满足），点击已选标签提示可清空筛选。详情窗口可以从同模款式下拉选择具体装备，各款的标签与收藏独立。

目录检索在独立后台执行并显示加载提示，连续改变条件只采用最新结果；取消标签不会阻塞角色预览和其他控件。查询失败可点击刷新重试。

所有支持部位共享随包提供的同模分组缓存，切换部位和翻页直接检索，避免重复计算整个部位的分组。缓存随原装备表SHA/格式版本校验并在失效时重建；收藏和标签独立保存，下一次主动查询重新排序的规则不变。

软件包是显式打包产物，平时修改`demo`源码即可，不在软件包内开发，也不随每次修改自动打包。发布时使用根目录“打包软件.cmd”；最终zip放在项目根目录，展开的软件文件夹保留在`artifacts/portable`。流程只收集应用依赖、必要运行表和默认`test.dat`。研究报告、图片、采集记录、参考仓库、测试脚本和历史预计算缓存不进入发行包。完整流程与限制见 [便携打包说明](../docs/portable-client-packaging.md)。
