# 幻化柜 PMX

本项目基于 [kilislan-wei / ffxiv_offline_glamour（幻化柜）](https://gitee.com/kilislan-wei/ffxiv_offline_glamour) 的官方 **v0.0.9 发行包中的应用源码与完整运行环境**，合入 PMX 导出、骨架方向修复、IK、表情和物理功能。这是独立维护的 PMX 修改版，并非上游官方发行版；保留原项目署名及 v0.0.9 的武器、情感动作、环境光/补光/独立灯光与抗锯齿功能。

源码在 [Gitee Fork](https://gitee.com/AyanamiDesu/ffxiv_offline_glamour) 的 `codex/pmx-v0.0.9` 分支维护，[GitHub 仓库](https://github.com/AstralZhao/ffxiv-offline-glamour-pmx) 提供镜像与便携版下载。Gitee 的 `master` 保留上游源码；PMX 分支继续使用已验证的 v0.0.9 基础，尚未合入上游后续版本的功能。

上游原创客户端源码采用 [MIT 许可证](LICENSE)，保留 Kilislan 的版权声明。游戏模型、纹理、图标和其他第三方内容适用各自的权利声明与许可条款。

## 下载与使用

1. 在 [Releases 下载页](https://github.com/AstralZhao/ffxiv-offline-glamour-pmx/releases/latest) 下载 `ffxiv-offline-glamour-pmx-v0.0.9-r2-windows-x64.zip`。为兼容 GitHub，下载文件使用英文名，解压后仍为中文目录与启动程序。GitHub 自动生成的 `Source code` 压缩包仅含源码，不是可直接运行的软件。
2. 完整解压到可写目录，双击 **幻化柜.exe**。已内置 Python 和依赖，使用者无需安装开发环境。
3. 首次启动选择匹配的国服 FFXIV 游戏目录或已有 `.ff14resources` 资源包；准备角色后，点击右侧 **导出 PMX 模型**。

使用条件：Windows 64 位及支持 Direct3D 11 的显卡。下载包不包含游戏安装数据或独立资源包。r2 修正了原始表情到 PMX 的转换，旧模型需要重新导出。更新时将新版本解压到新目录，再复制原目录的 `用户数据`，需要时也复制 `resources`；本修改版采用手动更新。

已完成内置运行环境下的解压启动、界面导出、58 项回归测试，以及龙娘多脸型和八种种族男女默认角色的导出检查。模型经 Blender / MMD Tools 导入验证；MikuMikuDance 主程序中的完整动作、表情叠加和物理仍需进一步验收。自动口型、复杂服装物理及特殊材质可能需要手动调整。详细范围见 [PMX 导出与验证记录](PMX_EXPORT.md)。

## 功能与开发说明

本分支新增 **导出 PMX 模型**：在右侧当前模版下方导出当前角色、可见装备与染色贴图，可供 MMD / PMX 编辑器使用。默认自动生成标准日文骨架、A 姿势、腿脚 IK、13 个基础表情及头发/尾巴/裙摆物理，也可保留当前姿势与原生骨架。自动表情、物理及 VMD 动作仍可能需要微调。完整说明见 [PMX 导出](PMX_EXPORT.md)。这个仓库只包含应用层源码，开发机安装 Python 3.11 或更高版本后可运行 `run-pmx-dev.cmd`，自动下载、校验匹配的官方运行包并启动本分支源码。

便携版为 `幻化柜-PMX-v0.0.9-r2-便携版.zip`，完整解压后双击 **幻化柜.exe**，无需安装 Python 或依赖。r2 根据当前脸型的原始表情生成眨眼、口型、微笑和眉毛，改善固定角度转换造成的变形；旧模型需重新导出。首次启动仍需选择匹配的国服游戏目录或已有资源包。PMX 定制版采用手动更新，避免被上游普通版覆盖。

以下数据路径相对于软件运行目录；通过开发入口运行时，该目录为 `local_runtime/dev-v0.0.9`。旧版 `local_runtime/dev` 保留，新入口不会混用其中的工具和运行表。上游研究文档的 `../docs/…` 链接属于完整源码布局，不随这个应用层仓库提供。打包、验收和后续测试范围见 [发行准备](PMX_EXPORT.md#发行准备)。

首次配置是独立窗口，只选择游戏目录或导入资源包。之后的“设置”分“资源、场景、存储”三页；存储页可查看软件文件占用和清理旧缓存，当前角色缓存、预设、模版、收藏与资源文件保留。统计和清理在后台进行。

“投影模版”中选中一套模版，点击“生成导出码 → 复制导出码”即可分享。点击“导入模版码”，粘贴后可修改名称并“新增模版”；导入保留已有记录，不会立即换装。代码包含装备和双染色，不含角色外观。旧保存记录无需迁移。另可使用“批量导出/批量导入”，勾选多套模版保存为一个.hggtemplates文件，或从文件中选择需要的模版新增；同名也新增，不覆盖已有记录、不立即换装。

“新建预设”提供人族、精灵族、拉拉菲尔、猫魅族、鲁加族、敖龙族、硌狮族和维埃拉族，共 16 种种族与性别组合。开发版首次启动会添加独立示例，之后保留你的修改；原有 `test.dat` 继续保留。每个组合的一个默认预设已完成资源加载与标准 PMX 导出验证，尚未覆盖全部部族、脸型、发型和体型极值。

“新建预设”可选择已支持的角色类型、部族和名称，生成独立DAT并预览。同名自动另存。已有预设的性别固定，编辑和保存接口均禁止改变；其他性别通过新建或导入另一份预设使用。男性不显示胸围选项，菜单和颜色按性别分别缓存。

便携软件包双击 **幻化柜.exe**，首次启动可选择“使用游戏目录”或“导入资源包”，保存后自动记住。“导入资源包”选择独立的`.ff14resources`文件，校验后保存在软件`resources`目录，无需原游戏安装目录。已有匹配国服客户端可在“设置”中导出资源包。以后从“设置”切换资源来源，保存并应用会在当前绘制结束后重新加载；版本失效时重新配置。运行环境随包提供，无需安装或选择Python。

资源包与客户端分别生成，这个源码仓库不包含游戏资源或 `.ff14resources` 文件。需使用本机匹配的国服客户端，或由匹配版本的软件导出资源包。默认导出会按依赖精简并重新整理索引，保留全部种族资源和各族装备变体，不降低模型/贴图质量；导出、导入均有进度并支持取消。迁移软件时保留已导入的 `resources` 目录。

右下角显示“泠雨@沃仙曦染”，旁边“操作说明”可随时打开完整使用指南。标签下拉框支持直接输入文字搜索已有标签，展开最多显示10项，更多内容使用滚轮浏览。

导入预设时同时准备并保存静态角色缓存；默认`test.dat`也已预先准备。切换优先使用最近4个角色的内存缓存，重新启动后复用磁盘缓存；预设内容、国服资源或相关渲染实现变化时重新生成。编辑外观的“更新模型”和“保存预设”仍分开。缓存机制及实测见[角色预览缓存](../docs/character-preview-cache.md)。

开发时双击项目根目录的 **run-pmx-dev.cmd**，将本仓库源码同步到 `local_runtime/dev-v0.0.9/demo` 后启动。修改本仓库源码后重新运行该入口；下载的原始压缩包保持不变。左侧装备目录、中央三维预览、右侧当前模版，顶部切换和编辑角色预设。不需要启动游戏或本机网页服务。客户端使用下载包中的 Python 3.11、NumPy、Pillow、PySide6 6.8.3 和 Windows Direct3D 11，优先使用独立显卡，无独显时使用可用硬件显卡。

D3D11在客户端原生窗口里直接显示，模型帧不经过GPU读回、PNG编码、HTTP传输或网页画布。原始材质先绘入FP16目标，最后在GPU上转换到窗口交换链。窗口大小改变时重建显示目标，保持原始材质流程。静态角色只在视角、尺寸或模版改变时重绘，连续拖动会合并到最新相机状态，不排队播放过时视角。

启动时先显示完整界面和加载动画，再后台准备角色与装备图标。加载角色、更新模型和换装绘制时显示旋转提示，并保留上一帧；相机拖动只在底部显示小提示，完成或失败后自动停止。

运行包提供默认 `test.dat`，首次启动会复制到 `用户数据/presets/test.dat`。预设列表只使用软件目录中的副本；顶部的“导入预设”按钮会新建一份原生 `.dat` 副本，同名自动另存。游戏里的原文件保持只读。

如果预设文件已导入但对应模型暂时无法加载，会保留文件和原画面，并提供编辑新文件的入口；可以先修改、保存，再单独更新模型。文件格式错误仍会明确拒绝导入。

点击顶部“编辑外观”，可修改发型、脸型、五官、身高、胸围、尾巴、颜色和彩绘等。“更新模型”只预览修改，不改所选DAT；“保存预设”只写入当前软件DAT，不更新画面。两项操作相互独立，界面会提示模型与文件是否一致。更新模型后会关闭窗口方便观察，再打开时保留尚未保存的预览。装备、染色和相机继续保留。首次生成新外观需要稍等；未能生成时保持原模型和文件。两个部族均可尝试；发型列表来自国服创建菜单，未知可见结构仍会提示原因。

- 按部位搜索名称、编号或标签。多个词用空格分隔，要求同时满足；`#礼服 #双染色` 或 `标签:礼服` 只匹配标签。目录全量开放，不限制获取、职业和等级。
- “图标 / 列表”切换，图标模式只显示装备图标，星标表示收藏，叠放标记和角标数字表示同模目录；悬停显示名称和标签，单击进入目录选择具体款式，单件装备直接试穿。装备与同模目录均按每页60项分页，可上一页、下一页或输入页码跳转；返回目录保留原页和滚动位置。
- 装备按同一部位、同一基础模型编号归为同模目录。目录名称和原始游戏图标采用整组中染色区最多的装备；数量相同时优先较新的装备编号。点击目录选择具体款式，返回时保留原搜索、已加载的分页和进入前的滚动位置。
- 点击装备换装，点击右侧模版卡片上的两个染色按钮分别染色。区域数量及染剂名称来自国服本机数据。
- 左键拖动旋转和俯仰，右键拖动平移，滚轮缩放；工具栏可切正面、侧面、背面或还原相机。
- 点击“保存模版”后，可从“投影模版”重新试穿。记录保存在 `用户数据/outfits.json`，不会改动游戏角色或安装目录。
- 武器支持独立分类、主副手试穿、染色与单独预览。角色模式导出 PMX 时，武器以当前形态绑定到独立控制骨并跟随实际挂点；武器单独预览使用原生导出模式，不生成角色 IK、表情和物理。

当前目录有20,519件防具和饰品。所有条目都可以发起共用渲染，部分特殊材质、骨架驱动和遮盖组合仍未实现；遇到这些情况会保留上次成功画面并显示原因。目录开放不代表每件装备均已成功绘制。

这些条目归为5,211组模型目录，左右戒指共用款式来源。搜索任何成员名称或编号都能找到所属目录，目录代表不会随搜索结果改名。原色变体和染色能力仍按具体装备保留。

防具和饰品共享本机EQDP模型选择与PBD逐层变形路径；不会因为共用模型来自其他基础体型就一律拒绝。没有本机资源或仍缺少实现的结构会明确提示。

头饰、衣服可按EST加载原始额外骨架，并连接到预设的固定站姿。变形缺少某个额外关节时，沿文件中的真实父级继承，不按名称猜测或填单位矩阵。支持调整的头饰可按游戏原始GMP参数与模型属性直接切换最终状态，入口仅在支持时显示；没有开合过渡、衣物摆动或装备物理动画。身体遮盖头部和高领遮盖头甲护颈也接入共用规则。规则与验证见[头部装备调整](../docs/head-equipment-adjustment.md)。

已接入滚动纹理、丝袜和玻璃三类原始着色程序：滚动纹理保持固定时间；丝袜读取额外的贴图坐标和原生皮肤材质；玻璃在不透明部件之后合成透射颜色与反射。它们仍使用原始染色表。当前是固定预览条件下的实现，尚未完成这些材质与游戏画面的逐项一致性确认。

普通半透明材质与`charactertransparency`使用原始颜色/透明度输出，在不透明部件之后排序合成；头发继续保留原有的主体和发梢两段流程。装备中的纹身、遮蔽材质复用既有叠加通道。相机会为翅膀等实际可见的大体积装备扩大取景，缩放范围为0.25至4倍。

装备贴花按原生IMC编号读取，使用独立的中性颜色乘数，不继承脸部彩绘颜色。头发按国服帽下发型模式控制，分别隐藏头顶、后发或全部头发，并应用原始帽下形变。预览处于未骑乘的固定站姿，因此坐骑EVP效果抑制标记不会阻止装备加载。

腰部、腿部护片、靴筒和护膝的遮盖按国服客户端条件组合，使用原始`shp_kos`、`shp_sho`等形变；尾部开口按预设种族筛选。长衣与裤靴模版不会再因为腿部护片标记而一律拒绝。

高领与头盔护颈、手套与上衣袖口按国服成组优先级和部位开关取舍；连体衣自身也会响应靴筒裁切。处理原始部件属性及模型形变，不改模型尺寸来掩盖交叠。

完全被装备遮住的饰品保留选择和染色，暂不加载绘制资源；脱下遮盖装备后自动恢复显示。已经隐藏的子网格上有形变重叠时，也不会再阻止整个模版。

连体衣遮住的防具、关闭显示的头饰也只保留选择与染色，不准备不可见模型和材质；仍会检查装备部位及染色是否合法。重新显示时恢复完整加载。隐形装备继续使用原始身体/内衣与占位网格，不一律当成空模型。

多个装备遮盖规则同时改变同一位置时，按原始模型文件中的形变顺序组合，后面的替换覆盖前面的；不再因为可见形变重叠而直接拒绝模版，也不依赖试穿的先后顺序。

少量装备引用的可选材质动画文件在本机不存在时，允许显示原始静态材质，并在预览下方提示。实际存在但尚未解读的动画文件仍会明确报错；这不代表已经实现材质动画播放。

预览支持已接入的装备及武器特效，可切换显示与播放；尚未支持的特效会提示。PMX 导出只包含模型和材质，不包含游戏粒子特效。

衣服材质本身的自发光继续显示，并通过显卡上的辉光合成呈现光晕（如新生女王礼服的蝴蝶结和裙侧）。它与附加粒子特效分开；颜色和发光区域来自原材质，辉光强度采用统一固定预览条件。

预览使用真实模型、骨架、原始材质与国服独立 D3D11 渲染流程。支持站姿、情感动作播放与面部表情；动作关联的物品和特效仍受上游支持范围限制。场景设置提供环境光、角色补光、独立灯光，以及 SMAA、2× 超采样、MSAA 4×。客户端记录上次预设、已绘制但未保存的外观、模版及相机；文件被外部修改时加载实际新文件，不自动覆盖。

动作播放期间导出时，标准 MMD 模式恢复角色与面部参考姿势，保持生成表情的中性基础；原生模式保存最后成功显示的一帧，重新计算仅在 GPU 更新的动画网格位置。两种模式都不会导出动画片段。

如需指定其他目录，可运行：

```powershell
python -X utf8 scripts/run_dev.py --game '游戏安装目录' --preset '外观预设.dat'
```

关闭客户端会先结束当前 GPU 操作再释放窗口资源。启动错误记录在 `缓存/logs/client-startup.log`；模型准备日志在 `用户数据/demo.log`。所有导入副本和模版都留在运行目录内。旧网页原型 `app.py` 保留作兼容入口，仍依赖完整运行目录；客户端本身不启动或依赖该服务。文件保存保留 SHA 冲突检查。

界面会随窗口变窄收紧侧栏，相机工具分行显示；默认窗口大小按屏幕可用区域设置。预设编辑按发型与体型、五官细节、颜色与彩绘分组。界面依赖版本记录在本仓库的 `requirements-ui.txt`，下载的运行包已包含这些依赖，正常启动无需另行安装。

右键装备图标或模版卡片可查看详情、编辑多个标签及收藏。悬停装备可查看名称和标签。“保存标签”只保存标签；独立的收藏按钮立即保存收藏状态，并保留尚未保存的标签草稿。自定义标签和收藏会长期保存在 `用户数据/equipment-library.sqlite`，不写游戏文件。武器使用独立分类与目录。

自动标签不再添加部位，旧的自动部位标签在下次启动时清理，用户标签保留。遮面、连体、长筒、过膝等覆盖类建议来自原装备模型配套的国服EQP规则；礼服、裙装、运动等风格仍是名称建议，详情会注明来源，均可纠正或删除。这不是完整的模型图像识别，尚未自动判定颜色、花纹或材质。染色能力标签保留。

装备收藏与“投影模版”分开：收藏或取消收藏后立即更新星标，但当前列表、同模返回和翻页不会重新排序；下一次搜索（也可按回车）、点击“刷新”或改变筛选时才按收藏优先排列。收藏的款式在其同模目录内优先，包含收藏款式的目录也优先，但目录名称和图标始终按最多染色区选代表。可点“★ 收藏”只看收藏，标签下拉可连续选择多个标签（同时满足），点击已选标签提示可清空筛选。详情窗口可以从同模款式下拉选择具体装备，各款的标签与收藏独立。

目录检索在独立后台执行并显示加载提示，连续改变条件只采用最新结果；取消标签不会阻塞角色预览和其他控件。查询失败可点击刷新重试。

所有支持部位共享随包提供的同模分组缓存，切换部位和翻页直接检索，避免重复计算整个部位的分组。缓存随原装备表SHA/格式版本校验并在失效时重建；收藏和标签独立保存，下一次主动查询重新排序的规则不变。

在 Windows 开发机使用 Python 3.11 或更高版本运行 `python -X utf8 scripts/build_portable.py`，即可在 `dist` 中生成便携 ZIP 和 SHA-256 校验文件。构建固定使用已校验的官方 v0.0.9 运行环境，按应用依赖收集源码并重建校验清单，包含五个 PMX 模块；不打入个人数据、导出模型、游戏资源、研究记录、测试脚本或开发缓存。已有同名输出需显式使用 `--overwrite`；后续修订可用 `--revision 3`。验收命令见 [发行准备](PMX_EXPORT.md#发行准备)。
